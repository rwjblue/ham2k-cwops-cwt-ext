# v0.3.4 — Cached RBN receiver locations

RBN · My signal now uses receiver grids and countries from the public RBN
node directory, improving map coverage when Vail ReRBN has no receiver grid.

- Ham2K saves the **RBN receiver directory** for offline use and checks for
  updates during data-file sync once the cache is older than seven days.
  Refresh it sooner in **Settings → Data Files** when a receiver moves or
  appears for the first time. The panel's refresh button updates reports only.
- Failed downloads and invalid directory responses retain the last good
  cache. Receivers absent from a later response are retained within a
  10,000-node limit, and directory updates apply to cached reports on the
  next panel render.
- Receiver matching preserves full callsigns, including skimmer suffixes.
  Vail's registered HamDB grid remains the fallback when the directory has
  no usable grid. Positions, distances, and bearings remain estimates.

Install the `.h2kext` bundle for each extension you use; matching `.sha256`
files accompany every bundle. RBN adds permission to access
`www.reversebeacon.net` alongside `vailrerbn.com` and still requires native
SVG panel support in Ham2K.

All four extensions use version **0.3.4**. CWT, MST, and SST behavior is
unchanged. RBN changes and personal packaging are exempt from the temporary
CWT upstream synchronization requirement.

Validation passed: **419 tests across 32 files**, lint, strict TypeScript
checks, official builds and packaging, and release checksum validation.
All four bundles passed the installed Ham2K Next **26.9.0 build 170** kernel
check, including registration of the new RBN data-file hook. No fresh native
installation or interaction test was performed for this release.
