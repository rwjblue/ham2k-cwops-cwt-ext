# v0.4.2 — Reception history and restart recovery

Keep recent PSK Reporter and RBN reports across restarts, recover recent PSK
history after collection gaps, and let explicit refreshes bypass local cooldowns.

## n1rwj-cwt

No extension-specific changes for N1RWJ CWT.

## n1rwj-mst

No extension-specific changes for N1RWJ ICWC MST.

## n1rwj-psk-reporter

- Request recent history when a panel opens, after collection gaps, and when
  expanding its report window. History and live MQTT reports share one bounded
  cache; newer observations win and reports retain their original timestamps.
- Space automatic history requests at least five minutes apart across panels,
  with longer backoff after failures. **Force reload** bypasses the local
  cooldown while still honoring offline state and sharing in-flight requests.
  Provider limits and browser challenges can still prevent backfill.
- Keep up to 1,000 reception links for one hour across extension/app restarts.
  Changed reports are saved at most every 30 seconds while rendering, so an
  abrupt close can lose reports received since the last checkpoint. Storage
  failures and incomplete windows are visible in Details.
- Support exact portable prefixes and suffixes in both reception directions,
  preserving slashes in displayed callsigns and HTTP queries.
- Add permission for `retrieve.pskreporter.info` for historical queries. Existing
  live reception continues if historical queries fail. Requires Ham2K build 171
  or newer; background capture and complete historical coverage are not promised.

## n1rwj-rbn

- Let **My Signal** manual refresh bypass the local cooldown immediately.
  Offline checks, shared server rate-limit backoff, and in-flight request
  deduplication still apply. Button labels and Details explain this behavior.
- Persist up to eight My Signal callsign/window snapshots, with up to 500 reports
  each and two-hour retention. Restored reports keep their original ages and
  check times and remain marked cached until a successful new request.
- Preserve request timing and shared server rate-limit backoff across restarts.
  Storage failures are shown without discarding the current session's reports.
- Retain automatic checks at most once per minute while visible. Returning
  after a long absence requests the selected window once; rapid tab switches
  reuse recent results. Native Spots keeps its existing polling cadence and
  report cache while sharing the persistent server backoff.

## n1rwj-sst

No extension-specific changes for N1RWJ K1USN SST.

## Repository notes

- All extension and workspace versions advance together to 0.4.2. There are no
  dependency updates or changes to contest behavior in this release.
- PSK Reporter and RBN reuse the persistent settings adapter in the reception
  workspace. This affects only those two extensions; the contest version bumps
  are personal packaging changes, exempt from upstream CWT synchronization.
- Validation includes deterministic restart, offline resume, cooldown, portable
  callsign, and SDK bridge tests, plus lint, typechecks, builds, and official
  packaging. These checks do not constitute native Ham2K lifecycle testing.
- Native portable delivery, full app restart/resume, and PSK history access still
  need runtime verification. The command-line PSK history probe encountered a
  Cloudflare challenge; backfill remains best effort.
