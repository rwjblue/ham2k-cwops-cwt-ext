# v0.4.3 — Preserve contest history after resumed scoring

Keep current-operation exchange suggestions ahead of downloaded history when
Ham2K resumes scoring from a named checkpoint.

## n1rwj-cwt

- Preserve exchanges from earlier contacts in the current operation when
  scoring resumes after an appended contact. Concurrent lookups share one
  membership reload, so downloaded history cannot override those exchanges.

## n1rwj-mst

- Preserve current-operation history after scoring resumes from a named
  checkpoint. The shared history adapter reloads membership once; received
  serial numbers remain per contact and are never history suggestions.

## n1rwj-psk-reporter

No extension-specific changes for N1RWJ PSK Reporter.

## n1rwj-rbn

No extension-specific changes for N1RWJ RBN.

## n1rwj-sst

- Preserve current-operation exchange history when scoring resumes from a named
  checkpoint, sharing one membership reload across concurrent lookups.

## Repository notes

- All five extensions and shared workspaces use synchronized version 0.4.3.
  There are no dependency updates in this release.
- The checkpoint regression covers current-operation precedence over a
  conflicting file record, concurrent lookups, and repeated lookups.
- Validation uses formatting, lint, strict TypeScript, deterministic tests,
  and official bundle/package checks. These are automated checks, not a
  native Ham2K UI test.
- CWT behavior is also maintained in
  [Ham2K/extensions PR #1](https://github.com/ham2k/extensions/pull/1).
  Sibling contest adaptations and personal packaging are outside that PR.
